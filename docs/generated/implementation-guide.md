# Nutrition Management — Implementation Guide

> Generated projection from accepted canonical project knowledge. Do not edit this file as a source of truth.

## Accepted realization

The terminal pre-code baseline selects Python 3.14, uv with committed lockfile, SQLite, Alembic, SQLAlchemy, SCIP through PySCIPOpt, deterministic CLI output and pytest plus architecture/structure checks.

These selections are implementation choices and do not redefine domain semantics.

Canonical source: `docs/redesign/implementation-design.md`.

## Dependency and component rules

Each context separates domain, application and infrastructure/adapters where applicable. Dependency direction is inward: infrastructure/adapters → application → domain. Composition is the only place that selects concrete implementations across contexts. Cross-context consumers use provider application contracts, never provider repositories or mappings.

PySCIPOpt is confined to the optimization adapter. SCIP status/types cannot cross that boundary. Reportable nutrition/cost/variety values are recalculated outside the solver.

Canonical sources: `docs/implementation/component-design.md`, `docs/redesign/component-design.md`, `docs/redesign/implementation-design.md`.

## Implementation sequence

The accepted sequence is: runtime/composition skeleton and dependency checks; persistence/migrations/provider contracts; Nutrition Targeting; Food Knowledge; Market Catalog; coherent Planning Input Source; Purchase Planning policy; SCIP adapter; post-plan gap enrichment; deterministic CLI; full verification gate.

A slice is complete only with design-derived verification evidence.

Canonical source: `docs/redesign/implementation-design.md`.

## Decisions coding may not make

Implementation must not invent new product scope, target semantics, context ownership, direct cross-context persistence, network interfaces, durable planning history, distributed integration, alternative result/failure semantics, weaker coherent capture, weaker optimization completion, or reinterpretation of nutrient evidence/safety/provenance.

If implementation genuinely needs one of these decisions, it must become an upstream Harness Question.

Canonical source: `docs/redesign/implementation-design.md`.

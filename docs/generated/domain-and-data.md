# Nutrition Management — Domain and Data

> Generated projection from accepted canonical project knowledge. Do not edit this file as a source of truth.

## Semantic ownership

Nutrition Targeting owns target derivation and source semantics. Food Knowledge owns food/nutrient evidence, taxonomy and external food-source normalization. Market Catalog owns executable SKU/offer semantics. Purchase Planning owns basket decision policy, outcome classification and reporting calculations.

Cross-context contracts expose provider-owned terminology and identifiers; persistence entities are never shared domain ownership.

Canonical sources: `docs/domain/strategic-model.md`, `docs/domain/context-map.md`, `docs/architecture/target-architecture.md`.

## Evidence and provenance

Unknown/trace nutrient evidence must remain distinguishable from known zero and quantitative evidence. Normalization preserves compatible component/unit/basis and provenance. Commercial observations preserve price/currency, observation time and supplied validity. The returned plan carries enough provenance to interpret the recommendation at calculation time.

The project does not promise exact historical replay of every candidate considered by a past run.

Canonical sources: `docs/requirements/product-requirements.md`, `docs/domain/nutrient-semantics.md`, `docs/architecture/target-architecture.md`.

## Persistence

The accepted implementation uses one file-backed SQLite database with context-owned tables, SQLAlchemy mappings confined to infrastructure and Alembic migrations. Cross-context foreign keys/ORM relationships are forbidden. Authoritative decimals are stored losslessly; dates remain dates; timestamps are explicit ISO-8601/UTC at persistence boundaries; currency remains explicit.

A Planning Input Snapshot is ephemeral and is discarded after the run. Saved plans/replay snapshots/planning-history tables require an upstream product decision.

Canonical sources: `docs/data/data-design.md`, `docs/redesign/implementation-design.md`.

## Temporal semantics

Target derivation uses an explicit date and versioned standard set. Market execution uses one explicit `as_of` instant. Offer observations preserve observation/validity facts. Current-clock defaults are not allowed for semantic dates/times. Later source changes do not retroactively alter the meaning/provenance of an already returned plan.

Canonical sources: `docs/architecture/target-architecture.md`, `docs/redesign/implementation-design.md`.

# Nutrition Management Strategic DDD model

Status: `draft`.

## Current accepted model

No product Bounded Contexts are accepted yet.

This is intentional. The repository bootstrap establishes the DDD process without inventing Nutrition Management semantics before problem/evidence and requirements work.

## Boundary acceptance criteria

A candidate Bounded Context should have evidence for a coherent combination of:
- ubiquitous language;
- authoritative responsibilities/decisions;
- semantic identity/lifecycle/invariants;
- authority boundary where relevant;
- stable semantic contracts to other contexts;
- independent change that is meaningful at the domain level.

A capability, use case, screen, service, database, package or deployment unit alone is insufficient evidence.

## Next domain action

When product evidence is available, derive only the capabilities required by accepted use cases, form context candidates, challenge ownership/boundaries with `docs/process/strategic-ddd-convergence.md`, and promote only accepted results here.
